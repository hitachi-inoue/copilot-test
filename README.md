## Product Backlog Item (PBI) タスク分解プロジェクト

このリポジトリは、Product Backlog Item（プロダクトバックログアイテム）をタスクに分解する例を示しています。

### 概要

アジャイル開発において、Product Backlog Item（PBI）は実装すべき機能や要件を表します。PBIをより小さく、管理しやすいタスクに分解することで、開発チームは作業を効率的に進めることができます。

### ディレクトリ構造

```
backlog/
├── pbi-001.json  - ユーザー登録機能の実装
├── pbi-002.json  - ログイン機能の実装
└── pbi-003.json  - 商品検索機能の実装
```

### タスク分解のガイドライン

1. **適切な粒度**: 各タスクは1〜2日（8〜16時間）程度で完了できるサイズにする
2. **明確な定義**: タスクの目的と完了条件を明確に記述する
3. **依存関係の明示**: タスク間の依存関係を明確にする
4. **テストの組み込み**: 単体テストと統合テストをタスクとして含める
5. **見積もりの記録**: 各タスクの見積もり時間を記録する

### JSONフォーマット

各PBIファイルは以下の構造を持ちます:

```json
{
  "id": "PBI-XXX",
  "title": "機能のタイトル",
  "description": "機能の説明",
  "status": "Ready/In Progress/Done",
  "priority": "High/Medium/Low",
  "estimatedPoints": 数値,
  "acceptanceCriteria": [
    "受け入れ条件1",
    "受け入れ条件2"
  ],
  "tasks": [
    {
      "id": "TASK-XXX-YY",
      "title": "タスクのタイトル",
      "description": "タスクの説明",
      "estimatedHours": 数値,
      "status": "TODO/IN_PROGRESS/DONE",
      "assignee": "担当者名 or null",
      "dependencies": ["依存タスクID"]
    }
  ]
}
```

### 使い方

1. `backlog/` ディレクトリ内の各JSONファイルでPBIとタスクの詳細を確認できます
2. タスクの進捗は `status` フィールドで管理されます
3. タスクの依存関係は `dependencies` 配列で管理されます
4. 各タスクには見積もり時間と担当者を割り当てることができます
